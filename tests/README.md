# Тесты для проекта FViZ

Этот каталог содержит юнит-тесты для проекта FViZ.

## Структура тестов

```
tests/
├── __init__.py
├── infrastructure/
│   ├── __init__.py
│   └── repositories/
│       ├── __init__.py
│       ├── test_entity_validation.py
│       ├── test_law_repository.py
│       ├── test_physical_quantity_repository.py
│       └── test_system_group_repository.py
```

## Технологии

- **pytest** - основной фреймворк для тестирования
- **pytest-cov** - для покрытия кода тестами
- **pytest-mock** - для мокирования объектов

## Запуск тестов

### Запуск всех тестов
```bash
source venv/bin/activate && python -m pytest tests/ -v
```

### Запуск тестов с покрытием кода
```bash
source venv/bin/activate && python -m pytest tests/ --cov=infrastructure --cov-report=html
```

### Запуск тестов для конкретного файла
```bash
source venv/bin/activate && python -m pytest tests/infrastructure/repositories/test_system_group_repository.py -v
```

### Запуск тестов с фильтрацией по маркерам
```bash
source venv/bin/activate && python -m pytest tests/ -m unit -v
```

## Конфигурация

Конфигурация pytest находится в файле `pytest.ini`.

## Покрытие кода

Тесты настроены на покрытие кода не менее 80%. Отчет о покрытии генерируется в HTML формате в каталоге `htmlcov/`.

## Примеры тестов

### SystemGroupRepositoryImpl
Тестирует основные операции с системными группами:
- Добавление, обновление, удаление групп
- Поиск групп по ID, названию, параметрам G,k
- Валидация уникальности

### PhysicalQuantityRepositoryImpl
Тестирует операции с физическими величинами:
- Сохранение и поиск величин
- Работа с видимыми величинами
- Обновление и удаление

### LawRepositoryImpl
Тестирует работу с законами и группами законов:
- Сохранение и поиск законов
- Работа с группами законов
- Обновление и удаление

### EntityValidation
Тестирует валидацию сущностей:
- Проверка форматов данных
- Валидация обязательных полей
- Обработка ошибок при создании сущностей

## Рекомендации

1. **Следуйте принципу AAA (Arrange-Act-Assert)** - каждый тест должен иметь четкую структуру
2. **Пишите осмысленные тесты** - тесты должны проверять конкретную функциональность
3. **Избегайте дублирования кода** - используйте `setup_method` для общей инициализации
4. **Тестируйте крайние случаи** - не только "счастливый путь", но и ошибки и граничные условия
5. **Держите тесты атомарными** - каждый тест должен проверять одну конкретную вещь
6. **Тестируйте валидацию на уровне сущностей** - создавайте сущности напрямую для проверки валидации
